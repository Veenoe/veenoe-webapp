# Start Viva curriculum

The active catalog is `data/curriculum/ncert-cbse-2026-27.json`. It covers classes 5–12 with 129 class-subject entries, 1,656 chapters and 985 suggested topics.

The data contains only:

- Class: `id`, `classLevel`, `subjects`.
- Subject: `id`, `name`, `chapters`.
- Chapter: `id`, `name`, `difficultyLevel`, `topics`.
- Topic: `id`, `name`, `difficultyLevel`.

IDs are unique within their parent. Array order follows the chapter list. Difficulty is `null` until a rating scheme is agreed; it is not displayed or sent to the viva. English and Hindi contain lessons as chapters with empty topic lists. Other subjects include a few familiar practice topics where useful.

The UI supports one class, one subject, one chapter, and multiple topics within that chapter. Selecting a chapter initially covers the entire chapter. Choosing preset or custom topics narrows that chapter's focus. “Entire chapter” clears those focus choices and is generated by the UI rather than repeated in the catalog. Students can add or remove their own single-line topics (100 characters each). Choosing a different chapter clears its topic choices; choosing the same chapter preserves them. Changing class or subject clears descendants.

Only the manifest is loaded eagerly. Selecting a class loads its separate JSON chunk; successful loads are cached and failed loads can be retried. Late responses cannot mark another class as ready. Selectors validate each loaded class once. The reducer stores chapter IDs, topic IDs and custom topic text. The original Quick Setup card uses standard class, subject and chapter dropdowns, a checkbox dropdown for multiple topics, with a custom-topic input and Add button at the top and a Confirm button at the bottom. Add queues a custom topic and clears the input for another; choices apply only after Confirm; closing the dropdown discards pending changes. Class selection is saved to `veenoe_last_class` and restored on load for classes 5–12.

The `curriculum_selection` request field contains `catalog_id`, `catalog_version`, class, subject and one selected chapter with its topics. The version is a content fingerprint of this curated dataset, not a textbook edition claim. An empty topics array means the entire chapter. The webapp owns the catalog. The backend checks request shape, class consistency, text limits and duplicates, then saves the client-supplied snapshot; it does not verify catalog membership or replace names. Custom-topic IDs identify student text rather than official headings. Only class and selected names reach the prompt; catalog identity and IDs stay in persistence. New requests require exactly one chapter. The backend stores the selection under the same name. The assessment must not claim that every chosen area was covered during a five-minute session.

Existing chapter mappings were retained where no better HTML list was available. Older editions are included where useful; this catalog does not claim exact alignment with one current edition. Topics are product suggestions, not an exhaustive list of official headings. No PDFs or images were downloaded for this revision.

Class 9 Interdisciplinary Area still has no reliable chapter list and remains visible but unavailable. Its empty list is not replaced with invented chapters.

Validation: frontend selection/catalog tests, backend request/prompt/persistence tests, TypeScript, changed-file ESLint and the production build. No browser testing was performed.

A student needs a nonblank profile name; the form no longer manufactures a “Student” name. The class preference key remains unchanged. Start stays disabled while subjects are loading or a name is missing.

To update catalog content, edit the source JSON and run from the webapp:

```powershell
node scripts/generate-curriculum.mjs
npx --yes prettier --write data/curriculum/manifest.json data/curriculum/class-*.json
```

The command regenerates only the webapp's class chunks and manifest. Frontend tests check their content fingerprint. Content updates within the current NCERT/CBSE curriculum catalog require only a webapp release, with no backend catalog update or coordinated release. Adding other boards, such as ICSE, state boards, IB or Cambridge, may require backend and prompt changes. Optional revision metadata is recorded as supplied by the client; it is not server-verified. Requests and saved sessions without revision metadata retain unknown provenance. Syllabus alignment relies on the UI and prompt, and still needs behavioral verification.
